# Brainatlas /process Implementation Plan - Batch Processing

**Created:** 2026-02-14  
**Status:** Planning  
**Goal:** Implement end-to-end batch processing: fetch papers → embed → summarize

---

## Overview

Enable brainatlas to process batches of papers for brain regions:
1. Generate search queries via LLM
2. Batch-fetch papers via fetcher
3. Generate embeddings for semantic search
4. Generate comprehensive summary
5. Deduplicate based on content hash

---

## Architecture Principles

**Batch-First Processing:**
- Wait for ALL papers for a region before processing
- One active batch per region at a time
- Batches are tracked end-to-end with UUIDs

**Content Deduplication:**
- Hash all source content (SHA-256)
- Skip expensive processing if content unchanged
- Store hash with summary for tracking

**LLM Query Generation:**
- Queries auto-generated by LLM initially
- Stored in DB for reuse
- User-editable via API (future)

**Separation of Concerns:**
- Fetcher: downloads papers, knows nothing about regions
- Orch: orchestrates batches, tracks state
- Brainatlas: processes content, generates embeddings + summaries

**Migration:** `orch/migrations/2026-02-14-000002-add-batch-processing/`

**New Tables:**

#### **region_queries**
Stores LLM-generated search queries for each region.

| Column | Type | Purpose |
|--------|------|---------|
| id | UUID | Primary key |
| region_id | INTEGER | Which brain region |
| query_text | TEXT | The search query |
| source | TEXT | 'llm_generated', 'user_added', 'user_modified' |
| priority | INTEGER | Query importance (future use) |
| enabled | BOOLEAN | User can disable without deleting |
| created_at | TIMESTAMP | When generated |
| updated_at | TIMESTAMP | When last modified |

**Unique Constraint:** One active batch per region
- Unique index on `(region_id)` WHERE `status IN ('collecting', 'ready', 'processing')`

**Why:**
- Prevents duplicate batches
- Enforces "one batch at a time" rule
- Allows historical batches after completion

#### **region_processing_batches**
Tracks batch processing lifecycle.

| Column | Type | Purpose |
|--------|------|---------|
| id | UUID | Batch identifier |
| region_id | INTEGER | Which brain region |
| status | TEXT | 'collecting', 'ready', 'processing', 'completed', 'failed' |
| fetch_task_ids | BIGINT[] | Array of fetcher task IDs |
| expected_task_count | INTEGER | How many tasks we're waiting for |
| content_hash | VARCHAR(64) | SHA-256 of all papers |
| created_at | TIMESTAMP | Batch started |
| ready_at | TIMESTAMP | All tasks completed |
| processing_started_at | TIMESTAMP | Brainatlas started |
| completed_at | TIMESTAMP | Summary generated |
| summary_id | UUID | Link to result |
| error_message | TEXT | If failed |

**Status Flow:**
```
collecting → ready → processing → completed
                                ↘ failed
```

**Indexes:**
- `(region_id, status)` - fast batch lookups
- Unique on `(region_id)` WHERE active - one batch per region

|--------|------|---------|
| id | UUID | Primary key |
| region_id | INTEGER | Brain region |

- `region_id → region_mapping.region_id` ON DELETE CASCADE

- `USING ivfflat (embedding vector_cosine_ops)` - vector similarity search

## Phase 3: Complete Data Flow

### 3.1 User Search → Batch Creation

```
User → POST /orch/api/regions/search { region_id: "uuid..." }
  ↓
[Orch API Layer]
1. Parse UUID → lookup region_id from region_mapping
2. Check if summaries exist:
   SELECT * FROM region_summary WHERE region_id = $1
   ↓
   If exists → return summaries + status=DONE
   ↓
3. Check if active batch exists:
   SELECT * FROM region_processing_batches 
   WHERE region_id = $1 AND status IN ('collecting', 'ready', 'processing')
   ↓
   If exists → return current status
   ↓
4. Create new batch:
   a. Get/generate queries:
      - Check region_queries for existing queries
      - If none, call LLM to generate N queries (N from config)
      - Store in region_queries with source='llm_generated'
   
   b. Create batch record:
      INSERT INTO region_processing_batches (region_id, expected_task_count)
      VALUES ($region_id, $query_count)
   
   c. Enqueue fetch tasks:
      For each query:
        POST /fetcher-be/api/queue/enqueue {
          query: "...",
          region_id: $region_id
        }
        → Returns task_id
   
   d. Update batch with task IDs:
      UPDATE region_processing_batches 
      SET fetch_task_ids = ARRAY[$task1, $task2, ...]
      WHERE id = $batch_id
  ↓
5. Return to user:
   {
     status: "FETCH_QUEUED",
     summaries: [],
     detail: "Collecting 3 papers for this region..."
   }
```

async fn run_completion_watcher() {
    loop {
        // STEP 1: Check collecting batches
        let collecting = infra.get_batches_by_status("collecting").await;
        
        for batch in collecting {
            // Check if all fetch tasks are complete
            let all_complete = check_all_tasks_complete(
                &batch.fetch_task_ids
            ).await;
            
            if all_complete {
                infra.update_batch_status(
                    batch.id, 
                    BatchStatus::Ready
                ).await;
            }
        }
        
        // STEP 2: Process one ready batch
        let ready = infra.get_batches_by_status("ready").await;
        
        if let Some(batch) = ready.first() {
            process_batch(batch).await;
        }
        
        sleep(interval).await;
    }
}

async fn process_batch(batch: &ProcessingBatch) {
    // Mark as processing
    infra.update_batch_status(batch.id, BatchStatus::Processing).await;
    
    // Collect all S3 keys from all tasks
    let mut all_s3_keys = Vec::new();
    for task_id in &batch.fetch_task_ids {
        let components = http_client
            .get(&format!("{}/api/queue/task/{}/components", fetcher_url, task_id))
            .await;
        all_s3_keys.extend(components.s3_keys);
    }
    
    // Call brainatlas to process
    match http_client.post(
        &format!("{}/api/process", brainatlas_url),
        &ProcessRegionRequest {
            region_id: batch.region_id,
            s3_keys: all_s3_keys,
        }
    ).await {
        Ok(result) => {
            infra.complete_batch(
                batch.id,
                result.summary_id,
                result.content_hash
            ).await;
        }
        Err(e) => {
            infra.update_batch_status(
                batch.id,
                BatchStatus::Failed,
                Some(e.to_string())
            ).await;
        }
    }
}

### 3.3 Brainatlas Processing (Updated)

```rust
// In brainatlas-be/crates/api/src/brainatlas_api.rs
async fn process_region(
    &self,
    region_id: i32,
    s3_keys: Vec<String>,
) -> Result<ProcessRegionResponse, Self::Error> {
    
    // STEP 1: Download all S3 files
    let mut full_content = String::new();
    for key in &s3_keys {
        let content = s3_client.download(bucket, key).await?;
        full_content.push_str(&content);
        full_content.push_str("\n\n---\n\n");
    }
    
    // STEP 2: Compute content hash
    let content_hash = sha256(&full_content);
    
    // STEP 3: Check if already processed
    if let Some(existing) = vector_db
        .check_content_hash(region_id, &content_hash)
        .await? 
    {
        return Ok(ProcessRegionResponse {
            summary_id: existing.id,
            chunks_processed: 0,
            was_deduplicated: true,
        });
    }
    
    // STEP 4: Chunk text
    let chunks = chunker::chunk_text(&full_content, 1000, 200);
    
    // STEP 5: Generate embeddings
    let mut embeddings = Vec::new();
    for (idx, chunk) in chunks.iter().enumerate() {
        let embedding = llm_client.generate_embedding(chunk).await?;
        embeddings.push(NewEmbedding {
            region_id,
            summary_id: Uuid::nil(), // temporary, will update
            chunk_index: idx as i32,
            chunk_text: chunk.clone(),
            embedding,
        });
    }
    
    // STEP 6: Generate summary
    let chunk_refs: Vec<&str> = chunks.iter().map(|s| s.as_str()).collect();
    let summary_text = llm_client.summarize(chunk_refs).await?;
    
    // STEP 7: Insert summary (with hash)
    let summary_id = vector_db.insert_summary(NewRegionSummary {
        region_id,
        name: region_name,
        acronym: region_acronym,
        summary: summary_text,
        content_hash,
    }).await?;
    
    // STEP 8: Update embeddings with summary_id and insert
    for emb in &mut embeddings {
        emb.summary_id = summary_id;
    }
    vector_db.insert_embeddings(embeddings).await?;
    
    // STEP 9: Return result
    Ok(ProcessRegionResponse {
        summary_id,
        chunks_processed: chunks.len(),
        was_deduplicated: false,
    })
}
```
